# Microgrid Touchtable - Developer Handover

Prepared: 1 October 2026

## 1. Purpose and current status

This project is an educational microgrid simulation based on DEMKit. Users place devices in houses and observe demand, solar generation, battery operation and grid constraints. The improved version adds learning goals, a coin budget, rewards, house feedback and battery strategy controls.

This is a development handover. The next developer can use this version as a starting point for improving installation and classroom use. The supplied runtime log shows simulation progress and successful EV creation, removal and reassignment requests. It also shows an InfluxDB connection failure.
## 2. Architecture

```text
Browser interface (localhost:3002)
    | user actions through Socket.IO
    v
Node.js / Express (web/index.js, port 3002)
    | HTTP commands
    v
Python / DEMKit (port 3001)
    | POST simulation state to Node.js at /dem/state
    v
Node.js broadcasts state to the browser through Socket.IO
```

The terminal windows display logs from the Python and Node.js processes. The terminal itself is not the middleware. Node.js provides the web interface and forwards commands; DEMKit and the Touchtable model perform the simulation. Frontend JavaScript handles presentation, interaction and game rules.

- Python dependencies are listed in `requirements.txt`. Most are not version-pinned.

- Configure InfluxDB if database logging is needed. Inspect `demkittt/conf/usrconf.py` and resolve connection errors before treating result storage as functional.
- Update the hardcoded paths in `touchtafel.bat` and `demkittt/conf/usrconf.py` if the checkout is not under `C:\Saxion_internship\Touchtable`.

### Launch

Double-click `workspace/touchtable/touchtafel.bat`, or start the two processes manually in separate terminals:

```powershell
cd C:\Saxion_internship\Touchtable\demkittt
python demkit.py -f touchtable/model -m touchtable
```

Wait until DEMKit reports that its interface is listening on port 3001. Then, in another terminal:

```powershell
cd C:\Saxion_internship\Touchtable\workspace\touchtable\web
node index.js
```

Open `http://localhost:3002` in a browser. The batch file does not automatically open a browser. Keep both program windows open while using the tool. Press Ctrl+C in each terminal to stop the corresponding process.

The backend starts paused. The mission overlay's **Start Mission** button starts simulation; the play/pause button also controls it. Dropping a device into a house adds it to the model but does not itself send the play command. If simulation is already running, the device participates in subsequent steps, subject to its state and controller.

The original web README describes a Docker workflow. Do not assume that workflow is equivalent to the current Windows launcher; container networking, environment variables and paths need validation first.

## 5. Example: adding an EV

1. The user drops an EV on a house in the browser.
2. `devices.js` checks placement through the game hooks and calls `addDeviceToDEMKit()`.
3. `sockets.js` emits `addDevice` with the device name, house number, type and scale.
4. `index.js` sends a command batch to DEMKit's `/synccmds` endpoint.
5. DEMKit creates the device, sets its parameters, connects it to the house meter and creates its controller.
6. DEMKit pushes state to Node.js, which broadcasts it to the browser for display.

Internal house indices start at zero: `SmartMeter-House-0` corresponds to the first house shown to the user. Moving a device out of a house requests removal; placing it in another house can recreate it there, so this should not be assumed to preserve device state.

An HTTP `200` means the request returned a successful HTTP response. It does not independently prove that every device parameter, learning goal or simulation result is correct. Current Node.js status logs do not identify which operation produced each status code.

## 7. Parameters and units

- Electrical power: W; capacity and state of charge: Wh; current: A; voltage: V.
- Simulation time step: 900 seconds, or 15 simulated minutes. This is not the wall-clock delay between updates.
- Current model: six houses, simulation starts on 1 January 2019, with no fixed interval count (`intervals = float('inf')`).
- Game defaults: 300 starting coins, three initial slots per house, 10 coins per slot upgrade. Prices and rewards are teaching rules, not market prices.
- Current house warning threshold is 0.85 in the relevant frontend constants. 
- Battery creation defaults at scale 1: 5,000 Wh capacity, 2,500 Wh initial state of charge, charging power range of -3,700 to +3,700 W.
- Solar mode allows charging from local surplus and blocks discharge for household load.
- Smart mode targets an 80% reserve and supports high household load, with a 20% discharge floor and a default 1,500 W load threshold. The implementation tests aggregate local net load, rather than directly identifying one particular appliance.
- Manual charge and discharge defaults are 1,000 W and 1,850 W, subject to energy, power and local-load limits.


## 8. Known issues and limitations

### Transfer and installation

- The working tree contains uncommitted modifications and untracked feature files. A clone of existing commits alone may omit the current improvements. Include changes from the outer, web and DEMKit repositories when preparing the handover snapshot.
- Paths are machine-specific. The launcher waits a fixed 30 seconds instead of checking backend readiness.
- Historical Node version declarations and Docker configuration need reconciliation with the actual working environment. `example.env` uses `DEM_IP` for the port value, while `index.js` reads `DEM_PORT`.
- The supplied runtime log contains InfluxDB connection warnings and an error. Simulation continued, but database storage has not been confirmed.
- `clearDB = True` attempts to clear the configured simulation database at startup. 


## 9. Validation checklist for the next developer

Record the environment, result and any errors for each check. These are proposed checks, not claimed passes.

- [ ] Install and start from a fresh copy on another computer.
- [ ] Confirm DEMKit port 3001 and Node.js port 3002 are available.
- [ ] Start Mission, pause and resume; confirm simulation time follows the controls.
- [ ] Add and remove each supported device type.
- [ ] Move an EV between houses; confirm backend membership and intended state reset behavior.
- [ ] Check budget deductions, slot limits, rejected drops and goal rewards.
- [ ] Test Solar, Smart, manual charge and discharge under appropriate load/solar conditions.
- [ ] Verify battery energy bounds and behavior with more than one battery in a house.
- [ ] Trigger overload feedback and a burned cable; reduce demand, restore the cable and verify supply returns.
- [ ] Test device resizing on real multitouch hardware and inspect changed backend parameters.
- [ ] Refresh or reconnect the browser and check interface/backend consistency.
- [ ] Stop DEMKit while Node.js remains running and verify useful failure handling.

During this handover preparation, syntax checks passed for `index.js`, `gamefication.js`, `devices.js` and `overloadWarnings.js`. No complete end-to-end or clean-install test was performed.
